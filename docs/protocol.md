# 串口通信协议（K230 视角）

K230 通过 **UART2** 与树莓派通信：**TXD = GPIO11，RXD = GPIO12，波特率 115200**，8N1。
树莓派侧是 USB 转串口，设备名 `/dev/ttyUSB0`。

数据格式极简：**每个指令就是一个字节，没有帧头、没有长度、没有校验和**。

> ⚠️ 因为没有帧头和校验，上电瞬间的线路噪声有可能被当成合法指令。
> 要长期使用建议改成 `[0xAA][CMD][CHECKSUM]` 帧格式。
> 当前版本保持原样，是为了与赛场上验证过的固件保持一致。

## K230 发送的指令

| 字节 | 名称 | 触发条件 | 树莓派侧动作 |
|---|---|---|---|
| `0x0B` | `MOTOR2_REV` | 目标偏右，`H > +30` px | 左右电机反转 50 步 |
| `0x0C` | `MOTOR2_FWD` | 目标偏左，`H < -30` px | 左右电机正转 50 步 |
| `0x0D` | `MOTOR1_REV` | 目标偏下，`V > +30` px | 上下电机反转 50 步 |
| `0x0E` | `MOTOR1_FWD` | 目标偏上，`V < -30` px | 上下电机正转 50 步 |
| `0xCC` | `DONE` | 目标已居中（`\|H\|` 和 `\|V\|` 均 < 30 px） | 电机失能，树莓派收工 |

## 树莓派发送的指令

| 字节 | 名称 | 含义 |
|---|---|---|
| `0xAA` | `READY` | 树莓派启动完成（`sleep(3)` 后发送一次） |

## 偏移量定义

`H` / `V` 是在 **1920×1080 的显示坐标系**下计算的，单位像素：

```
H = 检测框中心 x - 画面中心 x      H > 0 表示目标在画面中心右侧
V = 检测框中心 y - 画面中心 y      V > 0 表示目标在画面中心下侧
```

注意检测是在 640×360 的 AI 通道上做的，坐标要先按
`DISPLAY_WIDTH // OUT_RGB888P_WIDTH` 的比例换算到显示尺寸再算偏移。

## 控制逻辑

```python
if should_send:                                    # 限频: 每 200ms 最多一组
    if horizontal_distance >  DISTANCE_THRESHOLD:  uart.write(b'\x0B')
    elif horizontal_distance < -DISTANCE_THRESHOLD: uart.write(b'\x0C')
    if vertical_distance >  DISTANCE_THRESHOLD:    uart.write(b'\x0D')
    elif vertical_distance < -DISTANCE_THRESHOLD:  uart.write(b'\x0E')
```

* `DISTANCE_THRESHOLD = 30` px 是居中死区。
* `SEND_INTERVAL = 200` ms 是发送限频。
* 每收到一个字节，树莓派固定走 50 步（约 10 ms），走多远由发多少个字节决定。
  这是**纯 bang-bang 控制**，没有按距离比例调速，容易出现"走过头再走回来"
  的震荡。要改善可以按 `H / 50` 之类的方式动态决定步数（需要先扩展协议）。

## 已知的协议缺口

1. **`0xAA` 握手没有真正生效。** 本仓库的 `det_center_align_uart.py`
   **从不调用 `uart.read()`**，所以树莓派发来的 `0xAA` 一直留在 K230 的接收
   缓冲里没人取。也就是说 K230 无法确认下位机已就绪就开始发指令了。
   要修的话，在进入主循环前加一段读串口等 `0xAA` 的逻辑。

2. **`0xFF`（启动红外触发夹取）—— 这不是缺口，是职责划分。**
   本仓库所有源文件都不发这个字节，因为**红外夹取本来就不归 K230 管**：
   它是树莓派侧的一条独立本地链路，当年是在树莓派上**直接调用
   `handle_motor3_with_sensor()`** 触发的（比赛时在 REPL 里手敲），
   不经过串口。所以 `0xFF` 是树莓派侧一个从未被使用的预留入口。

3. **退出路径已补。** 原代码只在"本帧检测到目标"时判断是否居中退出，
   目标一旦丢失（遮挡 / 跑出画面）就永远卡在循环里，只能人工 Ctrl-C。
   现在连续 `MAX_LOST_FRAMES = 100` 帧未检测到目标也会退出。
